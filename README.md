# 🎨 Malooky — منصة الكاليجرافيتي العربي

منصة تعليمية متكاملة لتعلم فن الكاليجرافيتي (خط الجدران العربي العصري) — Next.js 15 + Supabase + Stripe + Bunny Stream.

| المجال | التفاصيل |
|---|---|
| 🎓 **كورسات بمستويات** | كورس رئيسي بمستويات متسلسلة (تأسيسي → متقدم) — الأدمن يضيف مستويات بأي أسماء |
| 🔗 **علاقات الكورسات** | `متسلسل` (يُفتح بعد 100% من السابق) أو `مستقل` (يُفتح مباشرة) |
| 📂 **أقسام فرعية** | تمارين (+ روابط Drive) · طريقة الكتابة · الأخطاء الشائعة · الفيد باك (نجوم) · الأسئلة الشائعة |
| ✅ **تتبع الإكمال** | إكمال كل فيديو — المستوى التالي يُفتح عند 100% فقط |
| 🌐 **دبلجة لغات** | كل لغة فيديو مستقل مرفوع منفصلاً — تبديل اللغة من المشغّل لكل الفيديوهات |

## 🚀 التشغيل المحلي والتحقق

استخدم Node.js المتوافق مع Next.js 15 (Node.js 20.9 أو أحدث) و npm. أنشئ إعداداً محلياً من القالب، ثم ثبّت الاعتماديات وشغّل الموقع:

```powershell
Copy-Item .env.example .env
npm ci
npm run dev
```

Next.js يقرأ `.env` و`.env.local` تلقائياً. الملفات المحلية مستثناة من Git؛ لا ترفعها ولا ترسل محتواها. بعد تغيير متغير بيئة، أعد تشغيل الخادم. عند غياب إعدادات Supabase ستعرض الصفحات المعتمدة على البيانات حالة تعذّر الإعداد بدلاً من بيانات وهمية.

قبل النشر، شغّل مجموعة الفحوصات نفسها محلياً:

```powershell
npm run lint
npm run typecheck
npm test
npm run build
```

يتطلب تشغيل الموقع للتصفح إعداد Supabase الصحيح. الدفع يحتاج مفاتيح Stripe وWebhook؛ تشغيل الفيديو يتطلب بيانات مكتبة ومفاتيح Bunny؛ رابط الخاصّة يحتاج رقم واتساب صالحاً. تظل صفحات الإعداد/المحتوى غير المهيأة متاحة للاختبار المحلي دون هذه الخدمات.

## 🌐 إعداد الإنتاج

1. جهّز قاعدة بيانات Supabase من SQL Editor بتطبيق `supabase/migrations/20260930000000_initial_schema.sql` ثم `supabase/seed.sql`. كلاهما قابل لإعادة التشغيل ويحافظ على قيم الإعداد التي عدلها المشغّل. لا يتضمن seed كورسات أو دروساً/معرّفات فيديو تجريبية؛ أدخل المحتوى الحقيقي من DASH. لمشروع قديم مطبق عليه المخطط الأساسي، طبّق فقط `supabase/migrations/20261001000000_admin_audit.sql` عند الحاجة. أنشئ Storage bucket باسم `manual-proofs` واجعله خاصاً من لوحة Storage؛ إعداد التخزين مستقل عن migrations.
2. أدخل متغيرات البيئة المطلوبة في بيئة الاستضافة قبل **البناء**، خصوصاً `NEXT_PUBLIC_*` التي تُضمّن قيمها في حزمة العميل. استخدم القيم الحقيقية لدى المزود فقط، ولا تضع أسراراً في المصدر.
3. وجّه DNS إلى منصة الاستضافة، واضبط `NEXT_PUBLIC_SITE_URL` على الأصل العام الذي يملكه المشغّل (بما فيه `https://`، بلا مسار أو شرطة مائلة أخيرة). لا يوجد نطاق إنتاج افتراضي في التطبيق؛ لا تستخدم عنواناً توضيحياً أو غير مملوك.
4. بعد ضبط المتغيرات ونطاق HTTPS، ابنِ وشغّل النسخة الإنتاجية عبر `npm run build` ثم `npm run start`، أو استخدم أمر البناء والتشغيل المكافئ لدى مزودك.
5. تحقق من الصفحة الرئيسية وتسجيل الدخول والكورسات، ثم اختبر Stripe test mode مع webhook قبل التحويل إلى مفاتيح live. اختبر رابط الفيديو وإعداد الدرس الخاص بعد ضبط خدماتهما.

لا يمكن إكمال إطلاق إنتاجي بهذه القيم القالبية؛ يلزم مشغّل يملك حسابات الخدمات والنطاق.

## 🔑 متغيرات البيئة

كل المتغيرات التي يقرأها التطبيق موضحة أدناه؛ القيم الحقيقية أو المفاتيح لا تُوفّر في المستودع.

| المتغير | مطلوب لـ | القيمة التي يضعها المشغّل |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | الموقع وواجهات البيانات | Project URL من Supabase |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | عمليات Supabase العامة/المتصفح | publishable/anon key للمشروع |
| `SUPABASE_SERVICE_ROLE_KEY` | صفحات وواجهات السيرفر والإدارة | service-role key؛ سري، للسيرفر فقط |
| `BUNNY_LIBRARY_ID` | تشغيل الفيديو | رقم Stream Library |
| `BUNNY_STREAM_KEY` | إدارة/التحقق من Stream عبر السيرفر | Stream API key؛ سري |
| `BUNNY_TOKEN_AUTH_KEY` | توقيع روابط تشغيل الفيديو | Token Authentication key؛ سري |
| `STRIPE_SECRET_KEY` | الدفع والويبهوك | Secret key؛ استخدم test أولاً ثم live |
| `STRIPE_WEBHOOK_SECRET` | التحقق من webhook | Signing secret الخاص بنقطة `/api/stripe/webhook` |
| `NEXT_PUBLIC_SITE_URL` | عنوان canonical في metadata وروابط رجوع Stripe | مطلوب للإنتاج: الأصل العام الذي يملكه المشغّل مثل `https://YOUR-DOMAIN`، بلا مسار أو شرطة أخيرة؛ قيمة localhost في القالب للتطوير فقط |
| `NEXT_PUBLIC_CURRENCY` | مبالغ Stripe | رمز عملة مدعوم من Stripe، مثل `USD` بعد اختيار المشغّل |
| `NEXT_PUBLIC_TRAINER_WHATSAPP_NUMBER` | رابط الدرس الخاص | اختياري؛ دولي بأرقام فقط مع رمز الدولة، بلا `+` أو مسافات. إذا غاب/كان غير صالح يظهر شرح الإعداد بدلاً من رابط. |

انسخ `.env.example` إلى `.env` للتطوير واستبدل placeholders محلياً؛ يمكن ترك `NEXT_PUBLIC_SITE_URL` فارغاً أثناء التصفح المحلي، لكن عندئذ لا تُنشأ جلسات Stripe checkout. في الاستضافة أدخل القيم في مخزن متغيرات البيئة، مع ضبط `NEXT_PUBLIC_*` لبيئة البناء وإعادة البناء عند تغييرها. لا تضع مفاتيح حقيقية في المصدر أو `.env.example` أو المحادثات. لا يختار التطبيق نطاقاً افتراضياً: عند غياب `NEXT_PUBLIC_SITE_URL` يُحذف رابط النطاق من التذييل ولا يُنشأ `metadataBase`، وتُعطّل جلسات Stripe checkout برسالة إعداد آمنة. عيّن الأصل الحقيقي الذي يملكه المشغّل قبل الإنتاج.

## 🗄️ قاعدة البيانات

شغّل `supabase/migrations/20260930000000_initial_schema.sql` ثم `supabase/seed.sql` في **SQL Editor** بلوحة Supabase. المخطط الأساسي ينشئ الجداول وRLS ومشغّل إنشاء ملف الطالب؛ seed يعيد إدراج إعدادات الموقع وطرق الدفع الافتراضية فقط دون استبدال قيم موجودة. لا توجد كورسات/دروس وهمية؛ أضف المحتوى الفعلي من لوحة الإدارة بعد إدخال بياناته.

ثم أنشئ Storage bucket باسم `manual-proofs` (**private**) لإيصالات التحويل اليدوي. يلزم حساب/وصول Supabase من المشغّل؛ لا ينشئه التطبيق تلقائياً.

لترقية قاعدة بيانات موجودة دون إعادة تشغيل المخطط الكامل، شغّل `supabase/migrations/20261001000000_admin_audit.sql` في SQL Editor. ينشئ هذا سجل تغييرات الأدمن المحمي بـRLS. يجب تشغيله قبل استخدام تبويب «سجل التغييرات»؛ إذا تعذّر التسجيل بعد نجاح إجراء إداري، ستظهر رسالة تحذير في اللوحة.

الكورسات الجديدة تُنشأ كمسودات. يتطلب النشر تأكيداً صريحاً، وعنواناً وسعراً صالحين (إلا إذا كان الكورس مجانياً) ومستوى ودرساً واحداً على الأقل. إلغاء النشر قابل للعكس ويحتفظ بالدروس والوصولات؛ الحذف النهائي للكورس معطّل من لوحة الإدارة لتجنّب فقد البيانات.

### أول حساب أدمن
1. سجّل دخول عادي من `/login` بعد إنشاء مستخدم من Supabase → Authentication → Add User.
2. في SQL Editor: `update profiles set role='admin' where email='osama@mail.com';`

## 🎥 إعداد Bunny Stream (أمان الفيديو)

هذه الخطوات تتطلب حساب Bunny ومكتبة Stream؛ أضف القيم الصادرة من لوحة Bunny إلى مخزن الأسرار/بيئة البناء وفق `.env.example`. من دونها لن تعمل مشاهدة الفيديو.

1. أنشئ **Stream Library** وفعّل **HLS AES-128 (File DRM)** من إعداداتها — هذا يشفّر الفيديوهات نفسها.
2. من إعدادات الـ Pull Zone فعّل **Token Authentication** وانسخ المفتاح إلى `BUNNY_TOKEN_AUTH_KEY`.
3. (اختياري لاحقاً) فعّل **DRM (Widevine/FairPlay)** لمعاقبة الأدوات الاحترافية.
4. ارفع الفيديو لكل لغة على حدة من Bunny → انسخ **Video ID** → اربطه بالدرس من DASH (🔗 ربط فيديو).

> ⚠️ **حقيقة تقنية**: منع تصوير الشاشة بكاميرا خارجية مستحيل تقنياً على الويب — لكن العلامة المائية
> المتحركة باسم/بريد المشاهد تجعل أي تسريب قابل للتتبع والمعاقبة قانونياً، وهي أفضل ممارسة عملية
> (نفس أسلوب Domestika وUdemy وMasterClass).

## 💳 إعداد Stripe

يتطلب الإعداد حساب Stripe ووصولاً إلى إعدادات Webhooks لدى المشغّل:

1. أضف `STRIPE_SECRET_KEY` في بيئة الخادم، وابدأ بمفتاح test.
2. أنشئ webhook عند `https://YOUR-DOMAIN/api/stripe/webhook` وحدد الحدث `checkout.session.completed`.
3. انسخ signing secret الناتج إلى `STRIPE_WEBHOOK_SECRET` في بيئة الخادم ثم أعد النشر.
4. اختبر checkout/webhook في test mode قبل استبدال القيم بمفاتيح live. لا تضع القيم الحقيقية في المستودع.

## 🌍 النطاق وHTTPS

النطاق ومزود الاستضافة غير مثبتين في هذا المستودع. يربط المشغّل النطاق الذي يملكه بمنصته وفق قيم DNS التي تعرضها المنصة؛ لا تنسخ سجلات نطاق توضيحي قبل مراجعة لوحة الاستضافة. بعد التحقق من HTTPS، عيّن `NEXT_PUBLIC_SITE_URL` إلى الأصل نفسه، ثم أعد البناء والنشر لأن القيمة عامة ومضمنة وقت البناء.
